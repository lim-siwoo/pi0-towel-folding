### pi0_aloha_towel이 이 로봇에 실제로 낸 높이 (ALOHA 기준, 변환 전)

| 실행 | 스텝 | 왼팔 최저 / 하위 10% | 오른팔 최저 / 하위 10% |
|---|---|---|---|
| 20261104-213941 | 1001 | 23 / 36mm | 27 / 40mm |
| 20261104-214102 | 5591 | 9 / 30mm | 23 / 42mm |
| 20261104-214405 | 15001 | −6 / 11mm | −11 / 18mm |

모델은 ALOHA 기준으로 책상에 닿거나 누르는 높이(≤ 40mm)까지 내려가라고 반복해서 명령했다. 지금 변환은 이 높이를 Trossen 베이스 기준 같은 높이로 그대로 보낸다. 그런데 Trossen 책상은 베이스 기준 −20mm로 입력돼 있고, 이 값은 측정한 값이 아니다. 그 결과 실제 그리퍼는 책상 위 수 cm에서 멈춘다. "허공만 헤집는" 증상과 맞는다.

### 불확실한 점 (2단계에서 측정으로 확인)

- 그리퍼 기준점이 두 로봇에서 같은 물리적 위치인지 모른다. ALOHA는 손목 회전축에서 107mm, Trossen은 마지막 관절에서 156mm이다. 손가락 중간인지 끝인지에 따라 수 cm 차이가 난다.
- Trossen의 실제 책상 높이와 기울기, 그리고 두 팔 베이스의 상대 위치를 아직 측정하지 않았다.

## 2단계: Trossen 실측 — `measure_trossen.py`

로봇 앞에서 실행한다. 정책 클라이언트는 꺼 둔다. 정책 서버는 켜 둬도 된다.

```bash
cd ~/pi0_aloha_towel/trossen_openpi/examples/trossen_ai && .venv/bin/python ~/pi0_aloha_towel/calibration/measure_trossen.py
```

준비:
- 책상에 공통 지점 3~4곳을 테이프로 표시한다. 수건 네 귀퉁이와 가운데 근처처럼, 양팔이 모두 닿는 곳으로 한다.

진행:
1. 시작하면 양팔을 그 자리에 고정한다.
2. 팔마다 `go`를 입력하면 그 팔만 힘이 풀린다(중력 보상). 손으로 받치고 움직인다.
3. 아래 세 항목을 순서대로 기록한다. Enter로 기록하고, `u`로 마지막 기록을 취소하고, `n`으로 다음 항목으로 넘어간다.
   - table: 그리퍼를 닫고 손가락 끝을 책상에 댄 점, 4곳 이상
   - grasp: 책상 위 얇은 물건을 집는 자세, 2곳 이상
   - common: 표시한 공통 지점, 3곳 이상. 양팔 모두 같은 순서로 찍는다.
4. 한 팔이 끝나면 그 자리에 다시 고정한다. 마지막에 양팔이 준비 자세 → 휴식 자세로 돌아간다.
5. `q`나 Ctrl-C를 누르면 양팔을 고정한 뒤 복귀한다.

결과:
- 원본 기록: `trossen_measurements_raw.json`
- 계산 결과: `trossen_measurements.json` (책상 평면, 집는 높이, 권장 Δz, 오른팔 베이스의 상대 위치)
- 다시 계산만 할 때: `--compute-only`

가짜 드라이버로 시험했다. 정답을 넣고 돌린 결과(책상 −20mm, 집는 높이 10mm → Δz −32mm, 두 팔 900mm·180°)가 그대로 복원됐다.

## 3단계: 변환에 반영 (`trossen_aloha_real/height_calib.py`, 기본 켜짐)

- ALOHA → Trossen: `z_n = plane(x, y) + g + (z_a − 42mm)`. Trossen → ALOHA(관측)는 그 역변환이다. x, y와 방향은 그대로다.
- 바닥 보호: `z_n ≥ plane(x, y) + g − 2mm`. 모델이 ALOHA에서 책상을 누르는 높이를 명령해도 이 로봇으로는 누르지 않는다.
- 끄려면 `--no-height-calib`, 바닥 여유는 `--floor-margin-mm`로 바꾼다.
- 오프라인 확인: 15001스텝 실물 실행(`runs/20261104-214405`)의 모델 명령을 다시 넣어 비교했다.

  | | 책상 5mm 이내에 있던 시간 | 높이 중앙값 |
  |---|---|---|
  | 왼팔 보정 전 → 후 | 0% → 41% | 102 → 52mm |
  | 오른팔 보정 전 → 후 | 0.4% → 35% | 76 → 30mm |

  보정 후에는 명령의 약 1/3이 바닥 보호에 걸린다. 다만 그 실행에서 모델은 보정 없이 자기가 떠 있는 상태를 봤기 때문에 더 누르려 했을 수 있다. 보정 후 실물 실행에서 다시 확인해야 한다.

### 보정 방식

- 그리퍼 끝을 책상 여러 지점에 대고 관절을 기록해, 각 팔의 책상 평면을 구한다.
- 물건을 집는 자세(손가락 끝이 책상에 닿은 상태)에서 Trossen 그리퍼 기준점 높이 `z_grasp_wxai`를 잰다.
- 높이 보정값은 `Δz = z_grasp_wxai − z_grasp_aloha(≈ 40mm)`로 정하고, 변환할 때 팔 끝 목표에 더한다. 관측 쪽은 반대로 뺀다.

## 6단계: 카메라 시점 비교 (2026-11-05, `camera_compare.py`, `fetch_pi_frames.py`, `render_rigs.py`)

비교 이미지: `compare_views/sim_vs_real.png`(시뮬레이터 대 실제). 모델이 보는 224×224 비교 그림은 사람이 찍혀 있어 이 저장소에는 넣지 않았다.

- **cam_high**
  - PI 실제 영상: 책상이 화면 아래쪽에 작게 보이고, 위쪽 절반이 검은 커튼이다. 카메라가 더 높거나 멀거나 화각이 넓다.
  - Trossen 실제 영상: 책상이 화면 대부분을 차지하고 더 위쪽까지 올라온다.
  - 그래서 같은 책상 중앙 물체가 Trossen에서는 더 위쪽(먼 쪽)에 보인다. 모델이 먼 쪽으로 과하게 뻗던 현상(depth-shift로 보정)과 맞는다.

  - ALOHA 2(Menagerie) 시뮬레이터 cam_high는 PI 실제 영상보다 훨씬 가깝다. **PI 카메라 위치의 기준으로 쓸 수 없다.**

- **손목**: Trossen 카메라가 손가락에 더 가깝고 낮다(뒤 97 / 위 55mm, ALOHA 2는 121 / 86mm). 손가락이 화면 아래 모서리를 크게 차지한다. 닫을 때 높이가 37mm인 현상과 맞는다.
- **배경·조명**: PI는 검은 커튼에 어두운 책상, Trossen은 밝은 사무실에 나무 책상이다.

- **cam_low**: 손가락이 잘 보이지 않는다. 기록 영상의 관절값과도 일관되게 맞지 않았다(rms 50px 이상). 그래서 보정하지 않는다. 또 Trossen 시뮬레이터 cam_low 화각(125°)은 실제와 다르다(실제는 약 55~65°).

### 보정 방식 (`build_warp.py` → `view_warp.json`, 실행 코드 `trossen_aloha_real/viewpoint.py`)

- **cam_high**: 책상면 호모그래피를 쓴다. 같은 작업대 좌표(관절 변환과 같은 손가락 끝 기준)의 책상 위 점을 PI 영상에서 보였을 픽셀로 옮긴다. 결과는 약 8% 축소와 약 64px 아래 이동이다.
  - 선택 마스크: 책상 먼 쪽 모서리 + 30mm 너머(벽)를 검게 가린다.
- **손목**: 손가락 끝 앞 20mm에 그리퍼 축과 수직인 평면을 기준으로 한 호모그래피를 쓴다. 결과는 약 4~10% 축소와 약 35px 아래 이동이다.
- 모델 입력 크기(224)로 줄인 뒤 변환한다. 카메라당 1~2ms가 걸린다.
- 한계
  - 책상면에서 높이 떨어진 물체(팔 등)는 약간 어긋난다. 두 카메라 위치가 비슷해서(높이 차 16cm) 어긋남은 작다.
  - 배경·조명 차이는 마스크 말고는 보정하지 않는다.
